## Answers to the specific questions
1. The setState during render is fine. The stale-form risk is real: see #5.
2. Inside a `hidden` parent it's OK: the tabs measure 0 on mount, then the RO fires when the panel is shown and snaps the pill into place. With `overflow-x-auto`, `offsetLeft` ignores scroll and the pill scrolls with the tabs, so positioning is correct. The real problems are #2 and #3.
3. The toast is correct. The wrapper is a stable `role=status` (implicitly polite and atomic), inserting the keyed child gets announced, and removal doesn't. Showing the same message twice in a row isn't re-announced or re-animated, because the state doesn't change (this was already the case). See #10.
4. `calc(max(sibling-index() - 2, 0) * var(--duration-stagger))` is valid, survives Lightning CSS, and gives 0s, 40ms and 80ms in Chrome (verified). Chrome before 138 drops the declaration, so there is no delay. Transitioning `translate` works for the Switch but not for the Button (#6).
5. No leftovers in code or tests; only comments and docs (#14).
6. Every `text-[#383838]` sits on a fill that doesn't change with the theme (canary, coral, accent or sky), and the buttons inside the canary banners bring their own backgrounds. No dark-mode defect there. The real contrast problem is in the light theme (#4).
